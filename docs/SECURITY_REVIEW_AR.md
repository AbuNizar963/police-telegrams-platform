# تقرير مراجعة الأمان والجودة — منصة برقيات الشرطة

## النطاق والحالة

يوثق هذا التقرير المراجعة التي سبقت دمج PR #237 إلى `main` بالالتزام `b66cea90fdae31f8b2c21cbb31cef10cc55b377e`، وما بقي من نتائجها بعد فصل مصدر تطبيق Flutter عن `main`. لا يُعد التقرير اختبار اختراق خارجيًا أو شهادة اعتماد أمنية رسمية أو إثباتًا مطلقًا لخلو النظام من الثغرات.

أُبقيت إصلاحات الويب والخادم والاعتماديات على `main`. انتقل عميل Flutter وفحوصه إلى فرع تطوير مستقل `flutter-mobile-app`. يبقى الخادم على `main` مسؤولًا عن التحقق من الهوية والصلاحيات والجهة؛ إزالة عميل الهاتف من `main` لا تعني حذف API الذي يحتاج إليه التطبيق.

## إصلاحات الويب والخادم الباقية على main

- **صلاحيات الجهات:** تُشترط عضوية فعالة مرتبطة بجهة فعالة في مسارات القراءة والكتابة ذات الصلة. أُضيفت تغطية لمنع تسرب البرقيات والتقارير والإحصاءات والإشعارات من الجهات المعطلة، ولتقييد القراءة الإقليمية. بقيت صلاحيات مسؤول المنصة المقصودة ومسارات استعادة الجهة.
- **مهلة تحرير البرقية:** توحّدت قاعدة مهلة 48 ساعة بين الخادم والواجهة في دالة مشتركة مختبرة؛ ولا يتجاوز دور الإدارة العادي المهلة مثل مالك النظام.
- **Service Worker:** لا تُخزّن استجابات API أو البيانات الخاصة؛ تعالج التنقلات بطلب الشبكة أولًا مع استخدام shell الثابت عند انقطاع الشبكة. تُخزّن الموارد الثابتة فقط عند غياب ترويسة منع التخزين، ويُقيّد رابط فتح الإشعار إلى نطاق النظام.
- **اعتماديات Node:** ثُبّتت حدود النسخ المصححة لـ`body-parser` و`qs` مع تحديث lockfile. أظهر `pnpm audit --audit-level=high` في المراجعة عدم وجود ثغرات معروفة ضمن فحص ذلك الوقت.
- **إعداد Supabase:** صُحح اسم المفتاح في التوثيق ليتطابق مع إعداد الخادم، مع إبقائه خادميًا فقط.

## إصلاحات عميل الهاتف

إصلاح سجل cache غير المتصل واختبار تسجيل الخروج موجودان في فرع `flutter-mobile-app` مع ملفات التطبيق. هذه خاصية عميل، وليست بديلًا عن حراسة الخادم. وُثّق اختبار المرفق الذي يتجاوز 2MB في تقرير offline-first تاريخي؛ لا تمثل أرقام ذلك التقرير قياسات الإصدار الحالي.

## متابعة 2026-10-29 — تصدير الوثائق والإشعارات

**التصدير الرسمي:** كانت صورة الشعار تُعاد كاملة بصيغة Base64 ضمن استجابة tRPC ثم تُضمّن أكثر من مرة في HTML. قد يؤدي ذلك إلى تجاوز حد Vercel للطلب أو الاستجابة قبل تشغيل Chromium؛ تفرض Vercel سقفًا قدره 4.5 MB وتعيد خطأ 413 عند تجاوزه [1] [2]. أصبح API يعيد مسار التخزين الخاص نفسه بدل بيانات الصورة، ويُجلب الشعار عبر endpoint يعيد فحص الجلسة والعضوية. يضغط المتصفح الشعار قبل الرفع إلى 2.5 MiB كحد أقصى، ويُرفض تنزيل الشعارات القديمة الأكبر من 4 MB برسالة 413 واضحة. حد HTML صار 3.9 MB وحدا تحليل JSON للتصدير ورفع الشعار 4 MB، مع فحص حجم الطلب ورسالة عربية مفهومة قبل/بعد الإرسال.

**الإشعارات:** أصبحت أحداث طلب الإحالة واعتمادها ورفضها تُرسل إلى تطبيق الهاتف عبر FCM بالإضافة إلى Web Push. تُصفّى قنوات الدفع وصندوق الإشعارات إلى الأعضاء النشطين المرتبطين بجهة نشطة. أضيفت مدة صلاحية خمس دقائق، وتنظيف الرموز التي يرفضها FCM، ونص شاشة قفل عام لا يعرض سبب الإحالة أو محتواها؛ يتبع ضبط مدة الرسالة إرشادات FCM لتحديد TTL وفق حاجة الرسالة بدل ترك صلاحية طويلة افتراضيًا [3] [4]. أُضيف اختبار لعقد بيانات الهاتف.

**Service Worker:** يفتح رابط الإشعار على نطاق النظام فقط. وإذا انقطع الاتصال، يعود التنقل إلى shell الثابت؛ ولا تُخزّن استجابات API أو البيانات الخاصة.

**التحقق المحلي:** نجح `pnpm check` و`pnpm build` و319 اختبارًا في 50 ملفًا، إضافةً إلى Prettier و`git diff --check`. أنتج اختبار Chromium في وضع Vercel ملفي PDF وPNG فعليين بشارات ملفات صحيحة. وفي متصفح Chromium ضُغط شعار PNG من 4,336,864 بايت إلى 1,548,993 بايت مع الحفاظ على صيغة PNG. لم تُشغّل بعد فحوص GitHub Actions لهذه التغييرات؛ يجب انتظارها على PR قبل الدمج.
