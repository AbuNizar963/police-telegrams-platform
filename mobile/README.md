# تطبيق برقيات الشرطة للهاتف

تطبيق Flutter هو واجهة الهاتف لمنصة برقيات الشرطة، ويستخدم الخادم نفسه وقاعدة البيانات نفسها اللذين يستخدمهما موقع الويب. مصدر الحقيقة للويب والخادم والهاتف هو المستودع نفسه على `main`؛ لا تُطوّر نسخة خادم مستقلة لتطبيق الهاتف، ولا تستدعِ Supabase مباشرة من التطبيق. يمر الاتصال عبر API الخادم وtRPC، وتبقى المصادقة والصلاحيات وقرارات نطاق الجهة مسؤولية الخادم.

## المتطلبات والتشغيل

- Flutter 3.47.2 وDart الموافق له، كما يحدده GitHub Actions.
- Android Studio أو Xcode بحسب المنصة، ومحاكي أو جهاز اختبار.
- Node.js وpnpm لتشغيل الخادم واختبار عقد API المشترك.

من جذر المستودع:

```bash
cd mobile
flutter pub get
flutter run
```

عنوان الخادم الافتراضي مضبوط في `mobile/lib/api.dart`. لتغييره أثناء التطوير:

```bash
flutter run --dart-define=API_BASE_URL=https://your-server.example
```

وعند الاتصال بخادم محلي من محاكي Android:

```bash
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:3000
```

لا تضع أسرار الخادم أو المفاتيح الإدارية في التطبيق. لا ترفع ملفات Firebase المحلية الحساسة؛ راجع `FIREBASE_SETUP_AR.md` لإعداد الإشعارات.

## علاقة التطبيق بالويب والخادم

- يستخدم الويب والهاتف حسابات المستخدمين والجهات والبرقيات والصلاحيات نفسها.
- عند تغيير إجراء tRPC أو شكل بيانات المستخدم أو البرقية أو الجهة، افحص الويب والهاتف واختبر كليهما. يختبر `server/mobileApiContract.test.ts` أن الإجراءات المسماة في عميل Flutter ما زالت منشورة في خادم المستودع.
- لا تعتمد على إخفاء زر أو `mobile_access_policy.dart` لحماية عملية؛ يجب أن يفرض الخادم التفويض ونطاق الجهة في كل طلب.
- تغييرات قاعدة البيانات إضافية ومتوافقة: أضف ترحيلًا جديدًا، ولا تعدّل ترحيلًا مطبقًا، واختبر النسخة القديمة والجديدة من التطبيق في بيئة محلية أو staging قبل النشر.
- التخزين المحلي للقراءات أو صندوق الصادر لا يثبت نجاح الكتابة على الخادم ولا يتجاوز التحقق منه. عند تغير المستخدم أو انتهاء الجلسة، لا تعرض cache حساب آخر.

## التنسيق والاختبارات

من مجلد `mobile`:

```bash
./tool/format_dart.sh --check
flutter analyze
flutter test --concurrency=1 --reporter expanded
flutter build apk --debug
```

لإصلاح تنسيق Dart قبل المراجعة:

```bash
./tool/format_dart.sh --fix
```

تُشغّل GitHub Actions فحوص Flutter عند تغييرات `mobile/` أو `server/` أو `shared/` أو `supabase/`، بالتوازي مع اختبارات الويب والخادم والترحيلات. لا تستخدم formatter لإخفاء تغيير سلوكي أو ضغط الملفات في سطر واحد.

## إصدار Android

لا يُنشر إصدار جديد تلقائيًا مع كل دمج. لبناء APK موقّع ونشره، شغّل يدويًا سير `.github/workflows/flutter-mobile.yml` من فرع `main` بعد اعتماد التغيير وتوفير أسرار توقيع Android وإعداد Firebase. يتحقق السير من توقيع الحزمة وبصمتها، ولا ينشر الإشعار إلا إذا كانت جاهزية خادم الإشعارات معدّة. لا يملك تشغيل طلب الدمج أسرار التوقيع ولا ينفذ إصدارًا.

## الإشعارات والعمل دون اتصال

- يمكن أن تعرض الشاشات الأساسية بيانات قرأها التطبيق سابقًا عند انقطاع الشبكة.
- الكتابات والإحالات وتغييرات الحالة لا تعتبر ناجحة حتى يؤكدها الخادم؛ تعرض حالات الفشل أو التعارض للمراجعة.
- لا تُعطل قيود نوع المرفق أو حجمه أو التحقق من الجهة.
- اختبر تسجيل الدخول والخروج وانتهاء الجلسة وتبديل الحساب قبل اعتماد أي تعديل على التخزين المحلي أو المزامنة.
