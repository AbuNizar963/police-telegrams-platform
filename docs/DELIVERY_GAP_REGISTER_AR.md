# سجل مطابقة وثيقة التسليم

## منفذ في المستودع

- التخزين الدائم، ترقيم ذري، الجهات والعضويات، إحالة ذرية، Storage خاص وروابط موقعة.
- دورة حالات خادمية موسعة تبدأ بمسودة، أسباب الإرجاع/الرفض، سجل إجراءات، إصدارات، وبصمات المرفقات.
- الأرشفة الإدارية أصبحت soft archive؛ لا يوجد حذف مادي من مسار التشغيل.
- idempotency key للحفظ، pagination من الخادم، RTL، فلاتر، طباعة وتصدير PDF.
- تقارير خادمية بنطاق الجهة مع البحث والحالة والفترة الزمنية وتصدير CSV محمي من Formula Injection.
- واجهة رفع مرفقات مع تحقق MIME والحجم، قائمة مرفقات، روابط تنزيل موقعة قصيرة العمر، وتسجيل التنزيل في التدقيق.
- إحالة مركزية تغيّر الجهة الحالية والحالة إلى `forwarded` داخل معاملة واحدة مع سجل إجراء.
- واجهة صريحة لانقطاع الاتصال تمنع نجاح الحفظ الوهمي، مع ظهور أدوات دورة الحياة للأدوار المخولة.
- RLS مفعّل على الجداول، أسرار الخادم منفصلة، CI للفحص والاختبارات والبناء.
- اختبارات TypeScript والوحدة والبناء ناجحة محليًا.

## يحتاج إعدادًا أو اعتمادًا خارج Git

- تشغيل migrations على مشروع Supabase الفعلي ومراجعة سياسات RLS وStorage عليه.
- تفعيل النسخ الاحتياطي المستقل، تحديد RPO/RTO، وتنفيذ اختبار استعادة فعلي.
- توصيل خدمة فحص برمجيات خبيثة للمرفقات إن كانت مطلوبة.
- ضبط Vercel Preview/Production وSecrets وRedirect URLs.
- منح GitHub صلاحية Write للحساب المنفذ لرفع الالتزام.
- اعتماد سياسة الاحتفاظ، الحذف النهائي، ودرجات السرية، ومصفوفة الأدوار من مالك النظام.
- اختبار استعادة نسخة احتياطية في بيئة معزولة لا يمكن تنفيذه من هذا الـ Sandbox لغياب Supabase CLI وDocker.

## نتيجة التحقق المحلي

- `pnpm check`: ناجح.
- `pnpm test`: 30 اختبارًا ناجحًا.
- `pnpm build`: ناجح.
- فحص الملفات المعدلة عبر Prettier و`git diff --check`: ناجح.
- فحص GitHub Actions الحالي: آخر تشغيل منشور على `origin/main` ناجح، لكن الالتزامات الجديدة لم تُرفع لأن صلاحية GitHub الحالية قراءة فقط.
- لم يُنفذ `supabase db reset` لأن CLI وDocker غير متاحين في بيئة التنفيذ الحالية.
