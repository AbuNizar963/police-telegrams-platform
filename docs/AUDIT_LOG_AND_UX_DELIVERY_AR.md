# عقد تنفيذ سجل الإجراءات وتجربة التشغيل الموحدة

**الحالة:** خطة تنفيذ داخل المستودع، 2026-10-30
**النطاق:** `main` لخادم API والويب ومخطط البيانات، و`flutter-mobile-app` لعميل Flutter ونسخة عقد API المتوافقة.

## القرار المعماري

سجل الإجراءات مورد أمني مستقل عن سجل مسار البرقية. يبقى `telegram_actions` لمسار الحالة والإحالات، ويصبح `audit_logs` السجل المركزي للعمليات الإدارية والأمنية وتصدير الوثائق والمرفقات. لا يتصل تطبيق Flutter مباشرة بقاعدة Supabase ولا يملك سر خدمة.

لا يمكن ضمان عدم تعديل سجل يمتلكه مالك قاعدة البيانات المادي أو مزود الاستضافة، لكن التطبيق يفرض عدم التعديل داخل المخطط وقنوات التطبيق: مشغّل قاعدة بيانات يرفض `UPDATE` و`DELETE`، صلاحيات SQL لا تمنح تعديل أو حذف السجل لأدوار العميل، وسلسلة بصمات تجزئة تربط كل إدخال بسابقه لكشف العبث. تبقى النسخ الاحتياطية وسياسة الاحتفاظ ومراجعة الوصول مسؤوليات تشغيلية للجهة المالكة.

## عقد حدث التدقيق

كل حدث جديد يحمل على الأقل: `actorUserId` واسم المنفذ ولقطة الرتبة والدور وقت التنفيذ، `action`، وقت خادم UTC عالي الدقة، عنوان IP، `userAgent` ونوع الجهاز، نوع المورد ومعرفه، نطاق الجهة، وبيانات الإجراء. للأفعال الحساسة يسجل سبب العملية ولقطة قبل/بعد بعد تنقية الأسرار. تسجل المرفقات باسم الملف ونوعه وحجمه وبصمة SHA-256 فقط؛ لا تسجل كلمة مرور أو رمز جلسة أو رابط تنزيل موقّع.

الأفعال الموحدة ذات الأولوية: `telegram.create` و`telegram.update` و`telegram.delete` و`telegram.document.print` و`telegram.document.download` و`telegram.export.rows` و`telegram.export.workbook` و`attachment.upload` و`attachment.download`.

## API الموحد

يحافظ `auditLogs.list` على التوافق مع العملاء السابقين. يضاف `auditLogs.search` للواجهة الجديدة ويعيد صفحة مرشحة تحتوي `items` و`total` وبيانات الصفحة. المرشحات الخادمية هي: المستخدم/النص، نوع الإجراء، معرف المورد أو رقم البرقية، بداية ونهاية وقت الخادم، والصفحة. تبقى صلاحية القراءة مقتصرة على مالك المنصة أو `system_admin` أو `auditor` ذي النطاق المصرح.

تسجل إجراءات التصدير من الخادم. تسجل واجهتا الويب والهاتف طلب طباعة/تنزيل وثيقة البرقية عبر إجراء tRPC موحد قبل التنفيذ المحلي. لا يعد تسجيل الواجهة دليلاً على إتمام الطابعة أو حفظ الملف في الجهاز؛ هو دليل على صدور الأمر من حساب مصرح.

## تسمية التنقل المشتركة

تستخدم المنصتان هذه الأسماء العربية مع إظهار العناصر وفق الصلاحية:

- لوحة المتابعة
- البرقيات
- مركز العمليات والمواقع
- التقارير والتصدير
- إدارة الجهات
- الحسابات والصلاحيات
- سجل الإجراءات
- الإعدادات

لا تنقل الصلاحية إلى العميل؛ إخفاء عنصر قائمة لا يعوض تحقق API.

## الخرائط والخصوصية

تعرض الخريطة مواقع البرقيات المحفوظة فقط، وليست تعقباً حياً للأفراد. تستخدم Google Maps عند وجود مفتاح مهيأ، وتعرض بديلاً مفتوحاً غير متطلب لمفتاح للتمركز على نطاق المواقع وقائمة قابلة للفتح خارجياً عند عدم وجود المفتاح. تتحقق الواجهة من إحداثيات صحيحة ضمن النطاق الجغرافي قبل عرضها. يجب تقييد المفتاح في بيئة الإنتاج على نطاق الموقع وGoogle Maps JavaScript API فقط، ولا يوضع أي سر خدمة في `VITE_`.

## توزيع العمل

### فرع `main`

ينفذ ترحيلاً جديداً فقط لحقول السجل والفهارس ومشغلات النزاهة. لا تعدل الترحيلات المطبقة. يوسع طبقة `db` للكتابة بلقطة منفذ الإجراء، للبحث المرشح، ولسجل نسخ قبل/بعد. يربط الخادم إنشاء وتعديل وحذف البرقيات، رفع وتنزيل المرفقات، تصدير القوائم والملفات، وأمر طباعة/تنزيل الوثيقة. تحدث واجهة React سجل الإجراءات والفلاتر والتحسينات الموحدة للقائمة وخريطة البلاغات.

### فرع `flutter-mobile-app`

يستقبل نسخة متوافقة من عقد tRPC والمخطط والترحيل بعد مراجعة تغيير `main`. يحدّث Flutter ليستعمل `auditLogs.search` مع مرشحات وتحديث دوري قصير، ويسجل أوامر طباعة/تنزيل الوثيقة، ويوحد عناوين التنقل مع الويب. يبقى العمل دون اتصال للبرقيات منفصلاً عن سجل التدقيق؛ لا تصدر عملية حساسة من الطابور إلا عند استجابة الخادم.

## التحقق قبل الدمج

تضاف اختبارات لسياق IP والجهاز، صلاحيات سجل التدقيق، الفلاتر، لقطات قبل/بعد، سبب الحذف، وأحداث التصدير/المرفقات. تشغل فحوص TypeScript وVitest والبناء في `main`، و`dart format` و`flutter analyze` و`flutter test` في الفرع المتنقل. يراجع ترحيل Supabase محلياً في بيئة معزولة قبل تطبيقه على أي مشروع فعلي. لا ينشر أو يطبق ترحيلاً على الإنتاج ضمن هذا التغيير المحلي.
